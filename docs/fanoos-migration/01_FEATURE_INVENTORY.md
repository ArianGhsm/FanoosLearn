## Reading guide

Source prefixes are defined in `01_FORENSIC_AUDIT.md`: `DENT` is the clean canonical Dentistry1402TUMS baseline, `BOT` is `IntegratedDent1402Tums`, and `VOICE` is `VoiceTranscriberBot`. Storage paths below describe schemas/locations only; production data was not opened or copied. Endpoint names are legacy action names, not proposed FANOOS URLs.

Reuse decisions use the mandatory vocabulary from `01_REUSE_MAP.md`.

## Coverage notes

- No separate DentNote repository or unified DentNote schema was found after filename and content searches across the three relevant implementations.
- A general-purpose calendar was not found. The existing schedule behavior is a Dentistry term/TUMS Navid academic assistant and should be treated as connector evidence.
- Question generation exists as parsers/build scripts and generated banks, not as a clearly bounded multi-tenant authoring service.
- Monitoring is primarily script/systemd/live-probe based. No general metrics, tracing, alert-rule, or SLO stack was found in the inspected sources.
