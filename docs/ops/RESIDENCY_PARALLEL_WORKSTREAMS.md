Inputs are study-only exports, **never** full-sitting import payloads. Any ambiguous item is **pending**, not a guessed mapping.

## Single-writer release protocol (mandatory, ordered, fail-closed)

1. **Orientation and concurrency lock.** Confirm canonical `main`, checkout/release SHA, `docs/PROJECT_PRINCIPLES.md`, official year validity from catalog **and live DB**, active updater/deploy jobs, pending PRs and any other publication operator. Acquire the project's authorized **exclusive publisher/DB transaction lock** before data apply, plus a coordinator-only durable operation/receipt ledger stored in protected research operations storage. Do not invent a lock mechanism, disable workers, or bypass a live competing publisher; if exclusive ownership cannot be verified, stop mutation.
2. **Immutable input and idempotence audit.** Select exactly one worker/year/subject batch. Pin package filenames/hashes and original worker audit. Query live `bank_question_sources` and official scope; compare each question ID, stem, all options, original official answers, media and human-reviewed source records against the original **freshly regenerated** study export. Reject or remove previously applied rows from the proposed batch by a documented new, separate, immutable batch—not by altering old worker evidence. Search live source rows and private historical receipts for the same question + edition + chapter + page, and check published assessment source explanations. Never re-apply an existing row; retain human decisions.
3. **Source evidence and editions.** Verify actual private PDF object hash/edition/year official validity, a searchable **temporary PDF-derived page index** bound to that hash, continuous reviewed page→chapter mapping, the original PDF page and verbatim passage, printed vs PDF page translation, approved chapter scope and explanation/recorded answer consistency. Run the unchanged `scripts/references/apply_classification.py`, then **independent** `audit_private_study_batches.py` plus a separate quote/page reviewer. Record the source PDF/index hashes in the durable audit receipt, then remove the temporary index when no concurrent batch needs it. An auditor disagreement or contradictory answer makes the item *held*, even when the primary validator returns accepted. No nearest edition, chapter-number translation, inferred negative evidence or missing figures.
4. **Source-only transaction preview.** Use `scripts/references/import_verified_sources.php` in preview mode, against fresh authenticated live input and audited, exact-hash package. Require the exact intended row count; **questions_changed=0, choices_changed=0, answers_changed=0**. The only permissible bank mutation is addition of independently approved `bank_question_sources` records; no changes to question text, options, answer key, images, human decisions, attempts or legacy assessment snapshots. Freeze the input/hash/version between preview and apply.
5. **Recovery point and commit.** Independently finish a **new, complete, 54-file-equivalent only if that is the actual verified manifest** full production backup using the official documented `scripts/ops/backup.php` and `scripts/ops/verify-backup.php`. Record finalized path, UTC completion, manifest SHA, recovery scope and retention/disk check. No reliance on a timed-out job or on a research archive as a DB backup. Only then run the source-only importer **as authorized `fanoosupd`** with `--apply`, exact batch count, provenance audit SHA, verified backup and **previously nonexistent unique receipt path**. Read back transaction rows and hash/check the receipt; verify invariants and remaining unsourced counts. On any mismatch, halt subsequent publication and investigate (do not rerun blindly).
6. **Student assessment review and new version.** Read-only `scripts/references/audit_published_assessment.php` preflight for the **entire** existing frozen exam. Stop if any question/options/key/media drift; generate a diff allowing **only source-derived explanation/reference changes**. Publish the affected year/round using the canonical authorized `scripts/import/import-bank.php publish` review/publish workflow, exactly once per deliberate group of completed batches. Persist old/new assessment version, reviewer/actor authorization and historical-attempt preservation. Re-run the full frozen-exam previous/current comparison; any non-explanation difference is a failure. Do not publish when no sources were applied.
7. **GitHub/CI/deployment only for an applicable approved code/docs change.** Make all permanent documentation/code/catalog changes on a separate branch, request review, inspect exact diff, require **all applicable** CI checks green, merge, and independently confirm `main` SHA and post-merge CI. Use **official updater only** (never edit `/srv/fanoos/current` or immutable releases); record request ID, updater success, `check-sync.sh`, actual deployed SHA and public `/health`. A source-only DB insert is distinct from a Git merge or site deploy. If there is no approved code/docs delta, record why CI/merge/deploy are *not applicable*, never represent them as passed. Do not deploy an unrelated unreviewed `main` delta.
8. **Durable final checkpoint and anti-duplication ledger.** Log each stage as `NOT_STARTED / BLOCKED / VERIFIED / APPLIED / PUBLISHED / DEPLOYED` with UTC timestamps, worker, source batch and exact content hashes, live source-row IDs, receipt SHA, backup ID+verification, before/after DB counts, assessment old/new full-diff receipt, CI run+conclusion, PR+merge SHA, updater request/state, site health result, and pending issues. Track the immutable **batch fingerprint** (workspace/type/year/round/subject + sorted original question identities + study/decisions/audit hashes); before any new run compare it to prior applied and published fingerprints. A repeated package is a no-op/stop condition, not a second import or second exam version.

## Verification, failure recovery, and continuation

On a new chat, reconstruct state **from these repo docs, on-host handoffs, backup manifests and private import receipts**, not prior chat messages or assumptions. Independently cross-reference receipts with **live** `bank_question_sources`, the latest `bank_assessments` versions and actual releases. Each stage's failure is recorded with exact evidence and an explicit restart gate. For a failed preview, do not mutate anything; for failed atomic apply, verify rollback and uniqueness before retry; for failed post-apply verification, quarantine the batch and do not publish; for failed post-publish full diff, stop rollout and follow the documented assessment recovery path without erasing attempts; for failed CI/deploy, retain the last verified deployed version and the incident. Only resume the next safe stage after resolving the recorded blocker.

**Historical-protection rules:** no synthetic answers, no question/choice/answer rewrites, no human-source replacement, no overwritten private receipts, no guessed PDF pages, no altered prior exam snapshots/attempts, no offsite-backup claim unless independently observed. All public docs carry *identifiers and method*, private workspaces carry protected raw evidence.

**Publication order:** inspect W01→W08 in deterministic worker order; within a worker order by year then subject, and import one atomic batch at a time only when every gate is green. Blocked batches do not prevent later eligible workers from independent auditing. A skipped batch and its reason must be recorded to avoid repeated attempts. No speculative or automatic merging of different workers' decisions into one release.
